# Security notes and release checklist

- Authentication uses Supabase Auth. Admin role is stored in `profiles.role`; promote admins only through a trusted dashboard/SQL session.
- RLS and private Storage policies are the intended access-control boundary. Frontend route hiding is not security.
- Public project UUIDs are not used as sole authorization. Queries and Storage policies require a signed-in user with admin role or project membership.
- Storage URLs generated by the portal expire after five minutes. Avoid logging or sharing signed URLs.
- Never ship service-role keys, database passwords, R2/S3 secrets, or payment secrets to browser code.
- Payment records are manual bookkeeping only. No card data or online payment processing is implemented.
- Face recognition, AI face search, guest discovery, video streaming, and third-party notifications are not implemented.
- The current browser upload accepts only image MIME types and size limits; server-side file decoding, thumbnails, resumable uploads and upload retry queues are not implemented.
- Review consent, privacy notice, gallery expiry, backup and deletion processes before real client launch.

Before production, run role-separated RLS tests for admin, project client, and unrelated user; test invalid/expired sessions; inspect deployed client bundles for secrets; test upload abuse cases; test selection limit concurrency; and verify that download restrictions meet the actual contract. Do not treat this checklist as proof that those tests have already passed.
